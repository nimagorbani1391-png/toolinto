# Toolinto

مجموعهٔ ابزارهای فارسی برای کارهای روزمره، ساخته‌شده با Next.js، React و PostgreSQL.

## راه‌اندازی محلی

۱. از Node.js 22 استفاده کن (`nvm use`). فایل `.env.example` را به `.env` کپی کن و `DATABASE_URL` و `JWT_SECRET` را تنظیم کن. برای تولید راز جدید می‌توانی از `openssl rand -hex 32` استفاده کنی.

۲. برای دیتابیس خالی PostgreSQL، فرمان‌ها را به این ترتیب اجرا کن:

```sh
npm ci
npm run db:deploy
npm run dev
```

۳. برنامه روی `http://localhost:3000` اجرا می‌شود. برای فعال‌کردن `/owner`، ابتدا با حساب مدیر وارد شو، شناسهٔ آن حساب را از پاسخ `/api/auth/me` بردار و در متغیر سمت سرور `ADMIN_USER_ID` بگذار. در صورت خالی بودن این متغیر، دسترسی مدیریت بسته می‌ماند.

## انتشار روی دیتابیس موجود

پیش از ادغام یا انتشار، از دیتابیس پشتیبان بگیر و روند مهاجرت را روی یک نسخهٔ آزمایشی اجرا کن. اگر جدول‌های `User` و `Link` از نسخهٔ قبلی با `prisma db push` ایجاد شده‌اند و دقیقاً با مهاجرت `20260101000000_baseline` منطبق‌اند، فقط همان مهاجرت اولیه را به‌عنوان اجراشده ثبت کن، سپس مهاجرت مالکیت لینک‌ها را اعمال کن:

```sh
npx prisma migrate resolve --applied 20260101000000_baseline
npm run db:deploy
```

روی دیتابیس خالی، مرحلهٔ `resolve` را اجرا نکن. اگر دیتابیس قبلاً مهاجرت دیگری داشته یا ستون `userId` از قبل وجود دارد، قبل از اجرای فرمان‌ها وضعیت و ساختار آن را تطبیق بده. مهاجرت جدید لینک‌های قبلی را حذف نمی‌کند؛ مالک لینک‌های قدیمی که تا حالا ثبت نشده‌اند، خالی می‌ماند.

در تنظیمات میزبان، Node.js 22، `SITE_URL` دامنهٔ اصلی، `DATABASE_URL` و یک `JWT_SECRET` تصادفی جدید تنظیم کن. راز پیش‌فرض قبلی یا رمز ثابت پنل را دوباره استفاده نکن. تغییر ساختار نشست باعث می‌شود کاربران بعد از انتشار دوباره وارد شوند. اگر نسخهٔ قبلی با پنل عمومی مستقر بوده، تا زمان اعمال اصلاح مسیرهای مدیریت قدیمی را در میزبان مسدود و سوابق دسترسی را بررسی کن.

## بررسی کیفیت

```sh
npm run lint
npm run typecheck
npm test
npm run build
```

فرمان ساخت به دیتابیس چیزی نمی‌نویسد؛ مهاجرت مرحله‌ای جداگانه است. گردش کار CI همچنین مسیرهای ورود، مدیریت، کوتاه‌کردن لینک و شمارش کلیک را روی PostgreSQL آزمایشی بررسی می‌کند.

## نصب وب و ساخت APK

وب‌اپ فایل manifest و یک صفحهٔ جایگزین آفلاین دارد. ابزارها و APIها در کش مرورگر سرویس‌ورکر ذخیره نمی‌شوند و همهٔ ابزارها در حالت آفلاین قابل استفاده نیستند.

برای APK، با `bubblewrap init --manifest=https://YOUR_DOMAIN/manifest.webmanifest` یک بار `twa-manifest.json` بساز. مقدار JSON را بدون رمز در متغیر GitHub Actions به نام `TWA_MANIFEST_JSON` بگذار و `ANDROID_KEYSTORE_BASE64`، `BUBBLEWRAP_KEYSTORE_PASSWORD` و `BUBBLEWRAP_KEY_PASSWORD` را به‌صورت GitHub Secrets تنظیم کن. اگر قبلاً APK منتشر کرده‌ای، همان شناسهٔ برنامه و کلید امضا را نگه دار. سپس گردش کار `Build signed Android APK` را دستی اجرا کن؛ برای پیوند دامنه با اپ، فایل Digital Asset Links را روی دامنهٔ واقعی تنظیم کن.
